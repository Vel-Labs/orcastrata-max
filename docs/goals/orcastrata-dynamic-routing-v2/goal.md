# Orcastrata Dynamic Routing V2

## Objective

Make the visible Parent model the only model choice required for normal use.
Orcastrata must decide when delegation adds value, select an eligible worker,
execute the bounded task, and return a truthful result. Exact-model selection
and explicit fan-out remain optional overrides.

## Goal Oracle

The goal is complete only when one clean installed successor proves:

1. A normal natural-language task can use automatic routing without a worker
   model or provider in the request.
2. The Parent can keep simple work direct and delegate useful independent work.
3. Automatic routing selects from fresh exact capability, authority, privacy,
   billing, availability, cost, latency, and diversity evidence.
4. Exact-model and explicit multi-model requests remain exact and never
   silently substitute.
5. A new model on an approved transport is configuration data. A new transport
   still requires package-owned adapter code.
6. A real isolated implementation lane can edit an explicit existing-file set,
   run exact Parent-authorized validation commands, return the complete diff,
   and roll back from verified bytes.
7. Receipts never convert unknown quota, usage, capability, or post-start
   failures into success or `called: false`.
8. The implementation uses one task execution service, thin compatibility
   wrappers, and one compact direct-task receipt.
9. Superseded raw evidence and duplicate contracts are removed without losing
   the final proof boundary.
10. Focused, consumer, package, clean-install, natural-language, and live-route
    acceptance all pass for the exact frozen candidate.

## Design Rule

Be additive in capability and reductive in machinery. Preserve a compatibility
wrapper only when it has a real consumer. Preserve safety gates. Remove
duplicate lifecycle code, evidence, contracts, and model-specific transport
configuration after migration proof exists.

## Stop Rule

Do not weaken an authority, identity, billing, path, retry, or rollback gate to
make a test pass. After two failures with the same signature and no changed
hypothesis, redesign or split the affected milestone.
