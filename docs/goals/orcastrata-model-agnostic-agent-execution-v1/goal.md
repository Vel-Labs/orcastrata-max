# Orcastrata Model-Agnostic Agent Execution V1

## Objective

Make installed Orcastrata execute useful work through configured models. Let an
operator add an exact model through an approved runtime without a source-code
change for each model.

## Original Request

Fix Orcastrata so a normal task can be delegated and carried out properly. Let
the operator ask how to configure model X as an agent. Use Luna workers where
they reduce cost without weakening proof.

## Goal Oracle

The goal is complete only when the exact installed successor proves all of
these behaviors:

1. An operator configures a model that is not hardcoded as a route through an
   approved transport.
2. Orcastrata discovers the exact runtime and model without reading credentials.
3. A normal read-only task selects and calls a compatible external model once.
4. The returned artifact passes exact identity and schema validation.
5. Orcastrata reports configured, selected, called, completed, rejected, and
   usage states truthfully.
6. A controlled write runs only in an isolated worktree with exact changed-file
   evidence and Parent review.
7. An explicit three-model adversarial review creates three assignments rather
   than treating route order as fan-out.
8. The same journey works from the installed plugin projection.

Synthetic tests, route catalogs, disabled example bindings, historical
canaries, and source-only package checks do not satisfy the oracle.

## Current Tranche

Build the smallest installed read-only vertical slice with DeepSeek through
Command Code. Then generalize model declaration over approved transports before
adding controlled writes and explicit provider fan-out.

## Authority

- Source edits, tests, builds, local worktrees, local package creation, and a
  reversible local plugin install are approved for this goal.
- Bounded provider calls through existing Command Code, MiniMax, and Grok
  subscription sessions are approved after fresh exact-route preflight.
- Existing host-managed or external-profile credential mechanisms can be used
  opaquely. Do not inspect, copy, log, refresh, or request credential material.
- Network use is limited to the approved provider calls. Do not download
  packages or contact unrelated services.
- No push, publication, destructive cleanup, AOL mutation, finance work, or
  production protected-host deployment is approved.
- Billing must remain subscription-only. Metered fallback is forbidden.

## Architecture Boundary

- Keep transport implementations package-owned and digest-bound.
- Make exact model candidates declarative for approved transports.
- Keep executable paths, argv, endpoints, environment values, modules, tokens,
  and secrets out of user model configuration.
- Derive capability from fresh evidence for the exact provider, transport,
  model, adapter, and version.
- Keep task authority separate from model identity and capability.
- Preserve no silent substitution, one-attempt execution, and
  `execution_unknown` fail-closed behavior.
- Keep protected production under T062. Do not make T062 a prerequisite for an
  isolated task-scoped development task.

## Stop Rule

Do not call a provider until source-local focused tests and the exact session
and model preflight pass. Do not promote read-only proof to write proof. Do not
promote one model's proof to another model. After two failures with the same
signature and no changed hypothesis, stop micro-patching and redesign the
affected milestone. Continue other safe milestones when one provider is
unavailable.
